# A1道場 要件定義

## 1. 文書の位置付け

本書は、A1道場 初期版の正式な機能要件、非機能要件、データ要件を定める。画面ごとの表示・操作は `docs/screens.md`、配色・部品は `docs/design-system.md`、完成判定は `docs/acceptance-criteria.md` を正本として併用する。

## 2. 目的と対象範囲

IT・ネットワークの初学者が、ネットワークスペシャリスト科目A-1向けの240問を短時間で繰り返し学習し、弱点を把握しながら30問・50分の模擬試験に慣れるための、モバイルファーストPWAを提供する。

初期版はログイン、クラウド同期、SNS共有、ランキング、広告、課金、外部AI API、問題の管理画面編集、複数利用者の履歴分離を扱わない。

## 3. 機能要件

### 3.1 問題データ

- `data/questions.json`を問題データの唯一の正本とし、Reactコンポーネントへ問題文・選択肢・正解・解説を直書きしない。
- 240問、IDの1～240連番、重複しない`code`、A～Dの4選択肢、正解、解説、覚える一行、カテゴリ、難易度を検査する。
- 正式なデータ検査はNode.jsで実装する。検査スクリプトは`npm run validate:data`で実行でき、`prebuild`および自動テストから実行する。
- 既存のPython検査スクリプトは参考用・補助用として残してよいが、Pythonは必須開発環境としない。
- 選択肢をシャッフルしても、選択肢IDにより正解判定を行う。

### 3.2 通常演習

- 出題対象は、全問、カテゴリ、難易度、未回答、誤答、お気に入りで絞り込める。
- カテゴリは複数選択でき、問題数は5、10、20、30、全件から選べる。
- 条件に一致する問題数を表示し、0問の場合は開始不可と理由を表示する。
- 「ランダム」は、絞込み後の問題プールの出題順をシャッフルする意味とする。模擬試験以外では、対象プールから問題を間引かない。
- 各問は4択を1つだけ選択でき、未選択時は回答できない。回答後は選択を変更できない。
- 回答後に正誤、正解、解説、覚える一行を表示し、最終問題後に結果を表示する。
- 途中セッションは通常演習を1件だけ保存する。新規開始時に既存セッションがあれば、再開または破棄を選択させる。

### 3.3 復習・回答履歴

- 誤答、未回答、お気に入りの問題を再出題できる。
- 問題ごとに回答回数、正解回数、誤答回数、最終回答、最終正誤および時系列の回答履歴を保存する。
- 正答率の低いカテゴリを優先した復習導線を提供する。

### 3.4 模擬試験

- 模試は「固定模試1」「固定模試2」「ランダム模試」の3種類を提供する。
- 固定模試1は`question_set.id = mock_exam_1`の30問、固定模試2は`question_set.id = mock_exam_2`の30問を使用する。
- ランダム模試は、`status = active`の全問題から重複なしで30問を無作為抽出する。
- すべての模試は制限時間50分とし、試験中は正解・解説を表示しない。
- 前後移動、問題一覧、見直しフラグ、未回答数を含む終了確認、終了時または時間切れ時の一括採点を提供する。
- ランダム模試の途中再開では、出題問題と出題順を変更しない。
- 途中セッションは模擬試験を1件だけ保存する。新規開始時に既存セッションがあれば、再開または破棄を選択させる。
- 模試結果には得点、正答率、未回答数、所要時間、系統・カテゴリ別成績、見直し問題の結果、誤答一覧と解説を表示・保存する。

### 3.5 成績・苦手カテゴリ

- 全体、系統、カテゴリ、難易度別の回答数と正答率、未回答数、誤答問題数、お気に入り数、模試履歴を表示する。
- 系統別集計はカテゴリの既定値ではなく、各問題の`domain_id`を正本とする。
- 回答済み問題が3問未満のカテゴリは「判定中」とする。
- 回答済み問題が3問以上のカテゴリを、正答率の低い順、同率では誤答数の多い順に苦手カテゴリとして表示する。未回答問題は正答率計算に含めない。
- 学習日とは、`Asia/Tokyo`の日付で通常演習または模試に1問以上回答した日を指す。同日の複数回答は1日と数え、前日から連続する場合のみ連続学習日数を加算する。

### 3.6 設定・バックアップ・全消去

- テーマは端末設定・ライト・ダーク、文字サイズは標準・大・特大、選択肢シャッフルはオン・オフを選択できる。
- 難易度ごとの問題件数を表示する。0問の難易度は選択不可とし理由を表示し、少数でも1問以上あれば選択可能とする。
- バックアップは、問題別進捗と回答履歴、お気に入り、通常演習セッション、模擬試験セッション、模試結果、学習日記録、表示設定、データ形式バージョンをJSONで出力する。ルートには`backupVersion`、`exportedAt`、`appVersion`を必ず含める。
- 復元は確認後の完全置換とする。形式、バージョン、必須項目を検査し、不正時は理由を表示して既存データを変更しない。復元はトランザクションで行う。
- 全消去は確認後に、回答履歴、お気に入り、途中セッション、模試結果、学習日記録を削除する。テーマ、文字サイズ、その他の表示設定は保持する。

## 4. 非機能要件

### 4.1 UI・アクセシビリティ

- iPhoneを主対象とするモバイルファースト設計とし、320px以上で原則横スクロールを発生させない。PCでは最大幅1080px、問題本文は最大幅760pxを目安とする。
- 下部固定ナビゲーションは、ホーム・演習・模試・成績・設定の5項目とする。
- 本文は16px以上、問題文は18px以上、タップ領域は原則44×44px以上とする。
- 正解・誤答・見直しは、色に加えて文字、アイコン、枠線で区別する。アイコンだけのボタンには`aria-label`を付与する。
- キーボード操作、可視フォーカス、ライト・ダークモード、文字サイズ変更、`prefers-reduced-motion`に対応する。

### 4.2 PWA・オフライン

- manifest、ローカルアイコン、Service Workerを備え、初回のオンライン読込後は通常演習、履歴閲覧、模試をオフラインで利用できるようにする。
- 外部API・外部CDNへ依存しない。
- 更新検出時は「更新があります」と表示するだけで、自動更新・自動リロードしない。利用者の操作で更新を適用する。
- 通常演習・模試は回答および画面移動ごとに保存し、更新後も再開可能とする。

### 4.3 ルーティング・対応環境

- 公開先が未確定のため、初期実装は`HashRouter`を採用する。静的ホスティングでも直アクセスが失敗しないためである。
- 公開先でSPAフォールバックまたはリライトを保証できる場合に限り、将来`BrowserRouter`への変更を検討する。
- iPhone Safariおよび主要PCブラウザの最新安定版を対象とする。

### 4.4 開発・品質

- アプリ開発、正式なデータ検査、テストはNode.jsで完結させる。
- TypeScriptはstrict設定とし、`any`を安易に使用しない。
- UI、ドメインロジック、永続化処理を分離する。
- `npm run validate:data`、`npm run lint`、`npm run test`、`npm run build`、`npm run test:e2e`を成功させる。

## 5. データ・保存要件

- `id`と`code`は永続IDであり、学習履歴の参照には`code`を使用する。
- 問題の`domain_id`、`category_id`、`subcategory_id`は`data/categories.json`と整合させる。
- `law_standards_emerging`を含め、系統の表示・集計には問題単位の`domain_id`を使用する。
- `original_category_label`は初期版の画面、学習履歴、検索条件では使用しない。問題読込み時に削除・上書きせず、将来の移行互換用フィールドとして保持する。
- IndexedDBのDB名、テーブル、保存形式には明示的なバージョンを持たせる。移行なしに既存データを削除しない。
- 模試は開始時刻と締切時刻を保存する。画面復帰時は締切時刻との差から残時間を再計算し、締切後は自動終了・採点する。
