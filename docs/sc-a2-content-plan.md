## 2. 推奨カテゴリ構成

セキュリティを5カテゴリに分け、ネットワーク・データベース・システム開発・監査を独立させる。問題数が少なくなりやすい開発管理とサービス管理だけを1カテゴリにまとめる。両者は小分類と問題ごとの系統で区別する。暗号・認証を脅威から分離することで、初学者が「何を守るか」「仕組み」「管理」「対策の選択」「実装」の順に学べる構成にする。

| 番号 | ドラフトカテゴリID                  | 表示名                         | 学習内容の例・分類の境界                                                                    |
| ---- | ----------------------------------- | ------------------------------ | ------------------------------------------------------------------------------------------- |
| 1    | `sc_security_threats`               | 情報セキュリティ・脅威・攻撃   | 保護目的、脅威・脆弱性、攻撃の成立条件。攻撃の仕組みを問う問題を置く                        |
| 2    | `sc_crypto_auth_pki`                | 暗号・認証・PKI                | 暗号・ハッシュ・署名・認証・証明書の役割と使い分け。特定製品の設定操作とは分ける            |
| 3    | `sc_security_management`            | 情報セキュリティ管理・リスク   | 資産、リスク評価・対応、ISMS、規程、組織の責任・継続。統制の監査手続とは分ける              |
| 4    | `sc_security_assessment_controls`   | セキュリティ技術評価・対策     | 評価・診断と、攻撃やリスクに応じた管理策・防御・対応の選択                                  |
| 5    | `sc_security_implementation`        | セキュリティ実装技術           | 安全な通信、アクセス制御、設定、コード・入力処理などの具体的な実装判断                      |
| 6    | `sc_networks`                       | ネットワーク                   | 通信の流れ、プロトコル、アドレス、制御、管理、応用。暗号化・認証の実装を主に問う場合は5へ   |
| 7    | `sc_databases`                      | データベース                   | データモデル・設計、SQL、トランザクション、障害回復、応用。SQL攻撃の成立条件は1へ           |
| 8    | `sc_system_development`             | システム開発・セキュア開発     | 要件・設計・実装工程・テスト・導入・保守。工程としての安全性を扱い、具体的な防御コードは5へ |

| 10   | `sc_system_audit`                   | システム監査・内部統制         | 独立性、証拠、監査手続、統制の評価。管理策の運用主体としての判断は3・4へ                    |

カテゴリは「解答を決めるための主たる知識」で1つだけ割り当てる。複数分野にまたがる問題は副次的なシラバス対応・関連用語を編集台帳へ記録し、問題数を二重計上しない。

IDは名称変更に影響されない意味ベースの新規案であり、既存NWカテゴリIDを別の意味に転用しない。現在のカテゴリファイルはそのまま保持する。

本Phaseで確認したのは公式公開資料の所在と候補母集団である。425問すべての本文照合、重複件数、図表件数、年代別・カテゴリ別の採用可能数は未調査であり、240問の一意な適格問題が確保できたと断定しない。

### 4.2 選定順序

1. 2023～2025年度の6回・150問から現行の論点を優先して台帳化する。
2. 2021～2022年度の4回・100問で類似問題とカバレッジを確認する。
3. 2017～2020年度の7回・175問から、不足する基礎原理・分野・難易度を補う。
4. 425問を出典単位で一覧化し、重複整理・現行適合性・図表対応を判定する。固定模試用50問を先に確保し、同じ重複グループを避けて通常演習190問を選ぶ。
5. 全7分野とセキュリティ5小分類の対応、カテゴリ9の両分野の件数を検証する。年度の新しさだけで採否を決めない。

年度別の採用数は実査後に確定する。9年すべてから均等に採用する義務は設けない。適格問題が不足した場合は、割当配分の再検討、最新の公開SC問題の追加候補、少数の明示的なオリジナル補助問題を別途提案する。未実施回や重複を水増しして240問にしない。他試験区分の問題をSC過去問として扱わない。

### 4.3 取込み手順・採用条件

後続作業では本番とは別の候補台帳を作り、`source_id`、問題PDF・解答PDFのURL、PDFページ、取得日・ファイルハッシュ、原文、原選択肢、公式解答、シラバス対応、重複グループ、図表要否、現行性、採否・理由、レビュー状態を記録する。原文と学習用の編集文を別欄に保持する。

OCRは転記の補助に限り、公式PDFと本文・選択肢・数値・条件・否定語・図表を目視照合する。公式解答のア／イ／ウ／エをA／B／C／Dへ対応付け、選択肢の原順序とIDを維持する。画面上でシャッフルしても正誤判定と選択肢解説はIDで対応させる。

採用条件は、出典と正解を追跡できること、現行範囲に対応すること、原文と図表を再現できること、独自解説がレビュー済みであること。解答例の訂正・更新も年度ページで確認する。

教育用途の利用ではIPAの出典明記・改変表示の条件に従う。転載と改題を区別し、第三者の解説サイトの文章は取り込まず、解説は独自作成する。図中などに第三者権利の表示がある場合は個別に確認する。[IPA FAQ「試験の過去問題の使用方法」](https://www.ipa.go.jp/shiken/faq.html)

## 5. 同一・類似問題の扱い

| 判定                                           | 処理                                                                                  |
| ---------------------------------------------- | ------------------------------------------------------------------------------------- |
| 本文・選択肢が同一（表記・空白だけ異なる）     | 1つの教材問題にまとめる。代表出典は新しく適格な回を優先し、他の出題回も台帳に残す     |
| 選択肢の順序だけ異なる                         | 同一グループとし、代表の公式解答と順序を採用する。正解記号を別回から流用しない        |
| 数値・名称だけ異なり、解法・判断が同じ         | 類似グループにまとめ、原則1問を採用する。数値の正規化は候補検出に限り、原文を変えない |
| 同一テーマでも問う判断・前提・誤答理由が異なる | 学習目標の差を説明できれば別問として採用できる                                        |
| 図表やコードが異なる                           | 文字列一致だけで同一とせず、図表の条件と解法まで確認する                              |

候補検出には空白・全半角などを正規化した本文・選択肢の比較と類似度を使い、最終判定は内容レビューで行う。暗号名、大小比較、否定語、数値、コードの記号は意味があるため、機械的に削除して同一判定しない。

240問全体で同一問題の重複を除き、原則として類似グループも通常演習・模試1・模試2の間で共有しない。同じ概念を別の判断で問うことは許容する。重複グループは出典IDの一覧で保持し、教材の `A2-xxx` をグループIDにしない。

## 6. 古い問題・範囲外候補の扱い

古い年度という理由だけでは除外しない。原理の理解に役立つ問題を残し、規格・法律・推奨設定・安全性の評価など時点に依存する問題を重点確認する。2026年の適合性確認に使った一次資料のURL・版・確認日と判断理由を台帳へ記録する。

| 編集判定                                   | 採用方針                                                                                         |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| 現行でも成立する原理・仕組み               | 採用可能。説明は現在の用語を補い、元の出典は維持する                                             |
| 旧技術の危険性や置換理由を学ぶ問題         | 原文の正解が今も成立する場合に採用可能。旧方式である旨と現行との違いを解説する                   |
| 法令・規格・推奨値の変更で判断が変わる問題 | 原文のまま本番教材・固定模試へ入れない。改題する場合は別途審査し、公式正解と編集後正解を区別する |
| 今のシラバスに直接の対応が確認できない問題 | 保留または不採用。NW固有の構成要素・ハードウェア問題を数合わせで残さない                         |
| 正解の根拠が曖昧、資料で検証できない問題   | 保留。解説の推測で公式問題を修正しない                                                           |

旧暗号・プロトコルを安全な推奨技術として説明しない。試験当時の公式正解は履歴として保存し、現行の理解と矛盾する問題は240問から外す。範囲外・古い問題の具体的な件数は候補台帳完成後に報告する。

## 7. 図表問題の扱い

本文、選択肢、表、ネットワーク図、時系列図、コード、数式のすべてを調査対象にする。図表問題を一律に除外すると学習内容が偏るため、適格問題を候補に残す。一方、現行A-2型には図表・添付アセットの項目や専用表示がなく、文字列に画像URLを埋めるだけでは実装できない。

- 単純な表は、意味・値・対応を保つ構造化表への転記を検討する。文章化・再作図した場合は改変を明記する。
- 接続関係や配置が判断に必要な図は、原図の忠実な切出し又は再作図を使い、ラベル・矢印・凡例を公式PDFと照合する。
- アセットは将来のアプリに同梱し、オフラインで参照できるローカル相対パスとハッシュで管理する。IPAへの外部リンクだけを問題表示に使わない。
- 320px・390px、ライト／ダーク、拡大表示、印刷された線や下付き文字を確認する。色だけに意味を持たせず、表は見出しと読み順を維持する。
- 代替説明は図の事実だけを説明し、解答に必要な推論結果や正解を先に書かない。選択肢に図がある場合も選択肢IDとの対応を保つ。
- 再現・アクセシビリティ・権利確認が完了しない問題は保留する。必要な図表表示を別Phaseで実装・検証するまで本番投入しない。

図表の件数や必要アセット数は未確定である。図表を除いた問題だけで240問を満たせるとは仮定しない。

## 8. 出典管理方法

### 8.1 既存構造でできること

確認対象は `src/types/question.ts`、`src/data/catalog.ts`、`data/a2-questions.json`、`scripts/validate-a2-data.mjs` である。

| 現行項目                              | 保持できる内容                                        | 制約                                                                                             |
| ------------------------------------- | ----------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 生JSONの `exam_id`、`subject_id`      | 試験区分識別子、科目識別子                            | `exam_id` は現行 `RawQuestion` / `Question` へ変換されない。`subjectId` はカタログから付与される |
| `source.basis`                        | 年度・期・試験・時間区分・問番号・URLを含む出典自由文 | 人には追跡可能だが、形式や公式解答との対応を検証できない                                         |
| `source.type`                         | オリジナル・転載・改題などの種別案                    | 現行型は単なる `string`。許可値・必須情報の検証がない                                            |
| `source.verbatim_past_question`       | 逐語転載かどうか                                      | 改変箇所や転載元の詳細は別途必要                                                                 |
| `correct_choice` → `correctChoice`    | アプリで使うA～Dの正解                                | IPAの原解答記号と解答PDFは保持しない。改題後は公式正解と同一とは限らない                         |
| `question_set.id / number / sequence` | 通常演習・固定模試の所属、模試番号・順序              | 出典の年度・問番号を表すものではない。流用しない                                                 |
| `metadata`、`schema_version`          | データ全体の説明、構造の版                            | シラバス版・教材改訂版を示す明示項目はない                                                       |

`category_drill` の実データでは `question_set.number` と `sequence` が `null` だが、現行 `QuestionSet` 型は `number` と宣言されている。この既存の型とJSONの不一致も将来のスキーマ整備時に確認する。本Phaseでは修正しない。

出典文字列を `source.basis` に書く方式で最低限の情報は格納できる。ただし現在の四肢択一画面は `source` を表示していないため、格納しただけでIPAの出典表示を満たしたとは扱わない。本番転載の前に出典表示と追跡検証を別Phaseで整備する必要がある。

## 9. 解説・memory_pointの作成ルール

### 9.1 既存項目での表現

`explanation` は1つの文字列、`memory_point` は1つの文字列であり、通常演習・結果・履歴画面で表示される。正解理由、各誤答理由、見分け方、関連用語は `explanation` に文章としてまとめられる。選択肢別の構造化解説・用語配列は現行型にない。

現行画面は文字列を `<p>` に入れるため、Markdownの見出しやリストを解釈せず、改行だけで読みやすい段落になる保証もない。既存互換の教材では「正解の理由：…。他の選択肢：Aは…、Cは…、Dは…。見分け方：…。関連用語：…。」のように短いラベルと文で区別する。長い解説を無理に1段落へ押し込まず、読みやすい構造化表示が必要なら別Phaseで設計する。

### 9.2 執筆・レビュー基準

1. **正解の理由**：最初に結論を書き、問題の条件から答えへ至る因果関係を説明する。計算は式・単位・代入・結果を示す。「正解はBです」だけで終わらない。
2. **他の3選択肢**：それぞれのIDと内容を対応させ、どの条件・目的が合わないかを説明する。正しい別技術なら「その技術が適する用途」も短く添え、技術自体が誤りだと断言しない。
3. **試験での見分け方**：条件の読み取り、技術の役割、似た概念の比較軸を示す。選択肢記号や語句の出現だけを暗記させない。
4. **覚える一行**：1つの原理・対比・公式を1文で表す。目安は日本語30～70文字程度とし、正確さを優先する。条件がある主張には条件を付ける。出典問番号や「Bを選ぶ」は書かない。
5. **関連用語**：2～5語を目安に、理解に必要な用語を選び、初出の略語には日本語の意味を添える。用語の羅列だけで説明を置き換えない。
6. **安全性・時点**：試験当時の条件と現行の推奨を混同しない。更新に敏感な説明には一次資料と確認日を台帳へ記録する。
7. **初学者向け**：前提の実務経験を求めず、「送信者・受信者」「守る対象」「攻撃が成立する条件」から説明する。文章を易しくしても原問題の難度や内容を勝手に変えない。
8. **解説の整合性**：公式解答、原文、選択肢、記述した理由を再照合する。シャッフル後もIDと選択肢内容の対応が崩れないよう、表示位置の「2番目」などを使わない。

将来の構造化案は `choice_explanations`（A～D別）、`exam_tip`、`related_terms`。既存 `explanation` を要約として残す任意追加とし、同じ内容の二重管理を避ける編集手順を決める。本Phaseでは追加しない。

### 11.2 模試の編集方針

模試は「複数回のSC過去問から構成した編集模試」を推奨する。特定の公式回25問をそのまま再現した模試とは表示しない。全7分野を各模試に含め、上表の配分、類似問題の分離、難度の均衡、図表の再現性を満たす50問を先に予約する。各問の実際の出典を表示し、模試番号を試験年度に流用しない。

各模試は通常演習と同じテーマでも別の判断を問う問題を選び、単なる記号暗記では解けない組合せにする。時間内で解ける文章量・図表・計算の偏りを確認する。模試内・模試間の同一問題を除き、`sequence` と配列の順序を一致させる。現行の固定模試選択処理は配列順を利用しているためである。

### 11.3 現行アプリの動作上の注意

現行 `filterPracticeQuestions` は `question_set` で除外しないため、通常演習で固定模試用50問も出題され得る。ランダム模試も全 `active` 問題から抽選する。190＋50は教材内の所属配分であり、50問を未見のまま隔離する動作ではない。このPhaseではこの動作を維持する。未見模試の専用プールが必要になった場合は別要件として検討する。

### 12.1 本番差し替え前の必須条件

1. 425問の台帳と採否理由を揃え、独立した適格問題240問と50問の模試を確定する。不足があればこの設計の配分案を再審査する。
2. 本文・図表・公式解答の照合、独自解説の内容レビュー、出典表示、スマートフォンとオフラインでの表示を完了する。
3. **同じ `a2`＋`A2-xxx` を別の内容に使う履歴リスクを解決する。** SC独立化後に旧NW教材を解いた履歴も対象になる。IDの枠を維持するだけでは安全な移行にならない。
4. 旧A-2の回答・お気に入り・途中セッション・模試結果・カテゴリ条件・旧バックアップ・同期済み項目を調査する。`src/domain/backup.ts` は現在の問題の正解と保存済み正解を比較するので、正解が変わる差し替えでは旧バックアップが拒否され得る。正解記号が偶然同じ場合でも、意味の違う履歴が混ざるリスクは残る。
5. 新規の空のSC利用開始では旧履歴の意味衝突がない。既存利用者への切替えは、旧教材と履歴を退避できる方式・明示的な移行方針を別Phaseで確定する。無断消去や、旧A-2の成績をSCの成績として引き継ぐ処理は行わない。バックアップの退避だけで新教材への復元互換を保証しない。
6. 科目BのA-2関連問題推薦は現在の小分類名・問題文と `data/b1-a2-topic-aliases.json` に依存するため、将来の差し替え時に推薦先も回帰確認する。今回は科目Bを変更しない。

### 12.2 2027年度への移行余地

教材メタデータに `dataset_id`、`content_revision`、`target_exam_year`、`syllabus_reference` を持たせる案を推奨する。構造の版 `schema_version` と内容の改訂版は区別する。現行の保存データは教材版を主キーに含めないため、メタデータを追加するだけで履歴の区別ができるとは扱わない。保存領域まで含む移行設計は別Phaseの課題とする。

問題の出典時点と学習対象年度を分離し、カテゴリ・割当・シラバス対応はデータ側に置く。画面・ルート・出典IDへ2026年度の分類や将来制度の仮定を埋め込まない。このPhaseでは2027年度用のカテゴリや教材を追加しない。
