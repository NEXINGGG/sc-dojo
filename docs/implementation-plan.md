# 実装計画

## 1. 前提

Phase 1は仕様確認と計画作成として完了している。本書では、以降の実装をPhase 2から記載する。

- 正式な問題データ検査、アプリ開発、テストはNode.jsで完結させる。既存のPython検査は補助用として維持する。
- 初期実装のルーターは`HashRouter`とする。公開先未確定でも静的ホスティングで直アクセスできるためである。
- 問題データの唯一の正本は`data/questions.json`とし、問題データは複製・編集しない。
- 各Phaseでは、対象機能のUnitテストまたはコンポーネントテストを同時に追加する。

## 2. 実装予定の構成

```text
src/
├─ app/                 # Router、AppShell、下部ナビゲーション
├─ components/          # 共通UI部品、ダイアログ、選択肢、アイコン
├─ data/                # 問題・カテゴリ読込み、型変換

├─ domain/              # 出題、採点、統計、復習判定の純粋関数
├─ features/
│  ├─ practice/         # 通常演習
│  ├─ review/           # 復習・お気に入り
│  ├─ exam/             # 模擬試験
│  ├─ progress/         # ホーム・成績
│  └─ settings/         # 設定・バックアップ
├─ hooks/

├─ styles/
├─ test/
└─ types/
public/icons/           # PWAアイコン
scripts/                # Node.js検査スクリプト
e2e/                     # Playwright
```

## 3. データ設計

### 3.1 型と問題データ

- `ChoiceId`は`A | B | C | D`とし、選択肢表示順とは分離する。
- 問題、カテゴリ、系統はJSONから型安全に変換する。
- `original_category_label`は問題型に保持するが、初期版の表示・検索・履歴には使用しない。
- 系統別統計は問題の`domain_id`を使用する。

### 3.2 IndexedDB

DB名は`a1-dojo`とし、Dexieの`version(1)`から開始する。以後の変更はバージョンを上げ、移行処理を追加して既存データを保持する。

| テーブル | 主な保存内容 |
|---|---|
| `questionProgress` | `code`、回答・正誤数、最終回答、最終正誤、お気に入り |
| `answerAttempts` | 問題別の時系列回答、回答日時、正誤、演習・模試の種別 |
| `practiceSessions` | 1件の途中演習、条件、出題順、選択肢順、現在位置、回答状態 |
| `examSessions` | 1件の途中模試、問題順、回答、見直し、開始・締切時刻 |
| `examResults` | 完了模試の得点、所要時間、系統・カテゴリ別成績、誤答コード |
| `learningDays` | `Asia/Tokyo`の日付ごとの学習実績 |
| `settings` | テーマ、文字サイズ、選択肢シャッフルなどの表示設定 |
| `metadata` | 保存形式・データ形式のバージョン |

バックアップはすべての学習データと表示設定を含み、ルートに`backupVersion`、`exportedAt`、`appVersion`を持つ。復元は完全置換とし、全検証後に単一トランザクションで実行する。全消去は`settings`を保持し、それ以外の学習データを削除する。

## 4. 状態管理とルーティング

- 永続化が必要な状態はDexieを唯一の正本とする。回答、見直し、画面移動時にセッションを保存する。
- 画面内だけで必要な選択中値やダイアログ開閉は`useState`または`useReducer`で管理する。
- テーマなど横断設定のみ小さなReact Contextで公開し、状態管理ライブラリは追加しない。
- 出題抽選、採点、正答率、苦手判定、連続学習日数はUIから分離した純粋関数にする。

| ハッシュパス | 画面 |
|---|---|
| `/#/` | ホーム |
| `/#/practice` | 演習条件 |
| `/#/practice/:sessionId` | 通常演習 |
| `/#/practice/:sessionId/result` | 演習結果 |
| `/#/exam` | 模試開始確認 |
| `/#/exam/:sessionId` | 模試中 |
| `/#/exam/:sessionId/result` | 模試結果 |
| `/#/progress` | 成績 |
| `/#/settings` | 設定 |

## 5. テスト方針

- Node.js検査：240問、ID・code・選択肢・必須フィールド、カテゴリ・小分類整合、重複、`mock_exam_1`・`mock_exam_2`の各30問を検査する。
- Unit：シャッフル後の採点、絞込み、出題順、30問抽選、模試採点、苦手カテゴリ、連続学習日数、タイマー、バックアップ検証。
- DB統合：保存・再読込、1件だけの途中セッション、完全置換復元、異常復元時のロールバック、全消去時の設定保持。
- コンポーネント：回答前後、次問遷移、0件条件、既存セッション確認、模試の見直し・終了確認、空状態。
- E2E：通常演習、固定・ランダム模試、途中再開、初回読込後のオフライン動作、更新通知の主要動線。
- 最終確認：320px、iPhone Safari相当、PC、キーボード、ライト・ダーク、文字サイズ、コンソール例外なし。
